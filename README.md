# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса (Альфа-Хак 2026).
Объединяет клиентский путь — от выбора продукта по потребности до получения средств — и внутреннюю
обработку заявки банком: валидацию, обогащение данными из БКИ / ЕГРЮЛ / ФНС, скоринг,
автоматическое решение и рабочее место кредитного специалиста.

## Быстрый старт

Нужен только **Docker 24+ с Docker Compose v2** (Docker Desktop на macOS / Windows или Docker Engine на Linux).

```bash
git clone <url-репозитория> && cd SOfE---AlfaHak
cp .env.example .env          # можно пропустить — есть значения по умолчанию
docker compose up --build
```

Первая сборка занимает 2–4 минуты. Когда в логах появится `Application startup complete`, откройте:

| Что | Адрес |
|---|---|
| **Кабинет (клиент и банк)** | http://localhost:3000 |
| Swagger UI backend | http://localhost:8000/docs |
| Моки внешних систем | http://localhost:8081/docs |

Остановить: `Ctrl+C` или `docker compose down`.
Сбросить все данные к исходным: `docker compose down -v && docker compose up --build`.

> Что изменено по сравнению с заготовкой — [CHANGELOG.md](CHANGELOG.md).

> Если порт занят (3000, 8000, 8081 или 5432 у другой программы), освободите его или поменяйте
> левую часть в `ports:` в `docker-compose.yml`.

## Сценарий проверки (5 минут)

1. **Одобрение и выдача.** Войти как `romashka` → «Получить кредит» → «Пополнение оборотных средств» →
   Далее → 2 000 000 ₽, 24 мес. → Далее → отметить согласие → «Отправить в банк».
   Заявка за секунду проходит проверку, сбор сведений и скоринг: статус **«Одобрено»**, скор 710,
   видны факторы решения и платёж в месяц. «Принять предложение» → отметить согласие →
   «Подписать и получить деньги» → **«Средства выданы»** и график платежей.
2. **Ручной разбор.** Там же: «Получить кредит» → «Покупка оборудования» → 15 000 000 ₽, 60 мес. →
   отправить → **«Рассматривает специалист»**.
3. **Работа банка.** «Выйти» → войти как `underwriter`. Во вкладке «Требуют решения» открыть заявку:
   данные БКИ / ЕГРЮЛ / ФНС, скоринг с факторами, долговая нагрузка. Выбрать «Запросить уточнения»,
   написать «Уменьшите сумму до 9 млн ₽» → «Принять решение».
4. **Уточнение клиентом.** Войти как `romashka`, открыть заявку: видно, что просит банк. Поменять сумму
   на 9 000 000 → «Отправить повторно» → **«Одобрено»**.
5. **Отказ.** Войти как `vasilek`, подать «Текущие расходы» на 1 000 000 ₽ → **«Отказ»** с объяснением
   факторов. `lyutik` — отказ по стоп-фактору ЕГРЮЛ. `petrov` на 300 000 ₽ — **контрпредложение**
   (180 000 ₽, ставка +3 п.п.).

Полный список с ожидаемыми результатами — [docs/test-scenarios.md](docs/test-scenarios.md).
Те же сценарии автоматизированы: `cd backend && uv run pytest`.

## Что реализовано

**Клиент:** вход; мастер «потребность → продукт → условия → проверка» с предварительным расчётом платежа;
данные компании подтягиваются из профиля, повторно не вводятся; прогресс заявки по этапам и подсказка
«что дальше» на каждом статусе; исправление данных по запросу банка; предложение банка (в том числе
контрпредложение с запрошенной суммой для сравнения); объяснение факторов решения; подписание
документов ПЭП (симуляция) и график платежей; автообновление статуса во время рассмотрения.

**Банк:** очередь с вкладками и поиском по названию / ИНН; карточка заявки с данными внешних источников,
скорингом, долговой нагрузкой и историей; решение специалиста — одобрить, контрпредложение с новыми
условиями, запросить уточнения, отказать (с обязательным комментарием клиенту).

**Конвейер:** машина состояний с журналом всех переходов (кто и когда); валидация → обогащение →
скоринг → решение в одной транзакции; повторы запросов к внешним системам; при недоступности источника
заявка уходит специалисту, а не «зависает»; разграничение доступа (клиент видит только свои заявки,
решения принимает только сотрудник банка).

## Локальная разработка без Docker

Нужны Python 3.12 + [uv](https://docs.astral.sh/uv/) и Node.js 20.

```bash
# 1. моки внешних систем
cd mocks && uv run uvicorn app.main:app --port 8081 --reload
# 2. backend (по умолчанию SQLite-файл local.db)
cd backend && uv run uvicorn app.main:app --port 8000 --reload
# 3. frontend на http://localhost:3000 (проксирует /api на :8000)
cd frontend && npm ci && npm run dev
```

Тесты и линтер: `cd backend && uv run pytest && uv run ruff check .`

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | `credit` | Параметры БД |
| `DATABASE_URL` | `sqlite:///./local.db` (вне Docker) | Строка подключения SQLAlchemy |
| `MOCKS_BASE_URL` | `http://localhost:8081` | Адрес сервиса моков |
| `CORS_ORIGINS` | `http://localhost:3000` | Разрешённые origin через запятую |
| `LOG_LEVEL` | `INFO` | Уровень логирования |
| `JWT_SECRET` | `change-me` | Секрет подписи токенов — **сменить вне демо** |
| `DEMO_MODE` | `true` | Показывать тестовые учётные записи на экране входа |
| `INTEGRATION_TIMEOUT_S` / `INTEGRATION_RETRIES` | `5` / `2` | Таймаут и повторы запросов к внешним системам |
| `MOCKS_LATENCY_MS` | `0` | Искусственная задержка ответов моков |

- Python 3.12: `backend/uv.lock`, `mocks/uv.lock`
- Frontend: `frontend/package-lock.json` (Node 20), сборка в Docker через `npm ci`
- Образы Docker закреплены по точным тегам

## Допущения MVP

- Внешние системы (БКИ, ЕГРЮЛ, ФНС) — локальные моки с упрощёнными контрактами (`mocks/app/data/registry.json`).
- Подписание документов и выдача средств смоделированы без реальных операций.
- Скоринг — прозрачная балльная модель, см. [docs/scoring.md](docs/scoring.md). ML/LLM не используются.
- Аутентификация — демо (логин/пароль, подписанный токен); в продуктиве заменяется на корпоративный IdP.
- Весь сценарий проходит внутри продукта, без email / SMS.
