# Скоринг и кредитное решение

Скоринг и решение разделены (см. кейс, стр. 14–15).

## Скоринг — `services/scoring.py`

Базовый балл **500**, к нему прибавляются факторы, итог ограничен диапазоном 0–1000.

| Фактор | Источник | Влияние |
|---|---|---|
| Просрочки > 30 дней | БКИ | −150 |
| Есть закрытые кредиты без просрочек | БКИ | +80 |
| Бизнес старше 24 мес. | ЕГРЮЛ | +60 |
| Бизнес младше 6 мес. | ЕГРЮЛ | −80 |
| Налоговая задолженность | ФНС | −100 |
| (сумма + текущий долг) / выручка > 0.5 | заявка + БКИ | −120 |
| (сумма + текущий долг) / выручка < 0.2 | заявка + БКИ | +70 |

## Решение — `services/decision.py`

1. Стоп-фактор (компания не найдена или не `ACTIVE` в ЕГРЮЛ) → **REJECTED**.
2. Сумма ≥ 10 млн ₽ → **UNDERWRITING** (ручной разбор специалистом).
3. Скор ≥ 600 → **APPROVED** на запрошенных условиях по базовой ставке продукта.
4. 450 ≤ скор < 600 → **COUNTER_OFFER**: 60 % суммы, ставка +3 п.п. Если 60 % меньше минимальной суммы
   продукта — **REJECTED**.
5. Иначе → **REJECTED**.

Один и тот же скор даёт разные условия для разных продуктов (базовая ставка, минимальная сумма).
К решению сохраняются ежемесячный аннуитетный платёж и список факторов — клиент видит их
в кабинете («Что повлияло на решение»), специалист банка — в карточке заявки.

## Ручной разбор

Андеррайтер видит скор, факторы, ответы БКИ / ЕГРЮЛ / ФНС и долговую нагрузку и принимает решение:
одобрить (можно скорректировать условия), контрпредложение, запросить уточнения, отказать.
Для отказа и запроса уточнений комментарий клиенту обязателен.

## Развитие

Пороги и премии по продуктам в конфигурации; калибровка весов на исторических данных;
статистическая модель (логистическая регрессия) вместо экспертных весов.
