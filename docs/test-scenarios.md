# Тестовые сценарии (E2E)

Предусловие: `docker compose up --build`, открыть http://localhost:3000. Клиент выбирается в шапке.

| # | Клиент | Шаги | Ожидаемый результат |
|---|---|---|---|
| 1 | ООО «Ромашка» | Новая заявка → Экспресс, 2 000 000 ₽, 24 мес. → Создать → Отправить | `APPROVED`, скор ≈ 710, предложение 2 000 000 ₽ / 22.5 % |
| 1a | — | продолжение п.1: Принять → Подписать | `SIGNING` → `ISSUED`, таймлайн показывает все этапы |
| 2 | ООО «Василёк» | Экспресс, 1 000 000 ₽, 12 мес. → Отправить | `REJECTED`, причина «Недостаточная скоринговая оценка» |
| 3 | ООО «Лютик» | Экспресс, любые параметры → Отправить | `REJECTED`, «Компания не действует по данным ЕГРЮЛ» |
| 4 | ИП Петров | Экспресс, 50 000 ₽ (ниже минимума) → Отправить | `INFO_REQUESTED` с текстом ошибки; после исправления суммы (`PATCH /applications/{id}`, в UI — TODO) и повторной отправки — решение |
| 5 | ООО «Ромашка» | Инвестиционный, 15 000 000 ₽, 60 мес. → Отправить | `UNDERWRITING`; решение через `POST /underwriter-decision` |
| 6 | любой | Отправить заявку в статусе `REJECTED` через API | `409 Conflict` |

Автотесты: `cd backend && uv run pytest`.
