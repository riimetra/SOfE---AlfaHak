# Изменения: рабочий прототип (ветка `nikita`)

Что сделано по сравнению с заготовкой (коммит `8636a13`) и как это запустить и проверить.

## Как запустить

Нужен только **Docker Desktop** (macOS / Windows) или Docker Engine + Compose v2 (Linux).
Перед запуском Docker Desktop должен быть открыт — иконка кита в строке меню не анимируется.

```bash
git clone https://github.com/riimetra/SOfE---AlfaHak.git
cd SOfE---AlfaHak
git switch nikita
cp .env.example .env
docker compose up --build
```

Через 2–4 минуты открыть **http://localhost:3000**.

| Сервис | Адрес |
|---|---|
| Кабинет клиента и банка | http://localhost:3000 |
| Swagger UI backend | http://localhost:8000/docs |
| Моки БКИ / ЕГРЮЛ / ФНС | http://localhost:8081/docs |

- Остановить: `Ctrl+C` или `docker compose down`
- Сбросить данные к исходным: `docker compose down -v && docker compose up --build`
- Автотесты без Docker: `cd backend && uv run pytest` (нужны Python 3.12 и [uv](https://docs.astral.sh/uv/))

### Тестовые учётные записи

На экране входа они показаны списком — достаточно нажать. Пароль у всех: **`demo`**.

| Логин | Роль | Что покажет |
|---|---|---|
| `romashka` | клиент, ООО «Ромашка» | Одобрение и выдача; от 10 млн ₽ — ручной разбор |
| `vasilek` | клиент, ООО «Василёк» | Отказ с объяснением факторов |
| `petrov` | клиент, ИП Петров | Контрпредложение (300 000 → 180 000 ₽) |
| `lyutik` | клиент, ООО «Лютик» | Отказ: компания ликвидирована по ЕГРЮЛ |
| `underwriter` | сотрудник банка | Очередь заявок и решения по ручному разбору |

### Проверка за 5 минут

1. `romashka` → «Получить кредит» → «Пополнение оборотных средств» → 2 000 000 ₽, 24 мес. → согласие →
   «Отправить в банк» → **Одобрено** → «Принять предложение» → «Подписать» → **Средства выданы**.
2. `romashka` → «Покупка оборудования» → 15 000 000 ₽, 60 мес. → **Рассматривает специалист**.
3. `underwriter` → вкладка «Требуют решения» → открыть заявку → «Запросить уточнения»,
   комментарий «Уменьшите сумму до 9 млн ₽» → «Принять решение».
4. `romashka` → открыть заявку → сумма 9 000 000 → «Отправить повторно» → **Одобрено**.
5. `vasilek` → любая заявка → **Отказ** с факторами; `petrov` на 300 000 ₽ → **Контрпредложение**.

Полный список сценариев — [docs/test-scenarios.md](docs/test-scenarios.md).

## Что сделано

### Было в заготовке

- Конвейер проходил основной сценарий, но многое было помечено `TODO`.
- Не было входа: клиент выбирался выпадающим списком, «банк» был открыт всем.
- Банковская часть — только таблица заявок; решение по ручному разбору — только через API.
- Новая заявка — ручной выбор продукта и три поля.
- Баг: при сбое внешнего сервиса заявка навсегда зависала в статусе «Отправлена» (повторная отправка давала 409).
- Не было `package-lock.json`, тесты покрывали только машину состояний.

### Backend (Python, FastAPI)

**Вход и роли** — новые `core/security.py`, `api/deps.py`, `api/routes/auth.py`, `seed_data/users.json`
- Вход по логину и паролю, токен `Authorization: Bearer` (HMAC-SHA256, 12 ч), пароли — PBKDF2 с солью.
- Роль `client` видит только заявки своей компании (чужие → `404`), роль `underwriter` — очередь и решения
  (клиенту → `403`).
- 5 тестовых учёток; `GET /auth/demo-accounts` для экрана входа (выключается `DEMO_MODE=false`).

**Надёжность конвейера** — `services/pipeline.py`, `integrations/external.py`, `api/routes/applications.py`
- Все этапы одной отправки — в одной транзакции: при ошибке заявка откатывается в исходный статус,
  клиент получает `503` и может отправить снова.
- Запросы к БКИ / ЕГРЮЛ / ФНС — с таймаутом и повторами (`INTEGRATION_TIMEOUT_S`, `INTEGRATION_RETRIES`).
- Источник недоступен → заявка уходит на ручной разбор с пометкой, какой именно
  (новый переход `ENRICHMENT → UNDERWRITING` в машине состояний).
- Компания не найдена в ЕГРЮЛ → стоп-фактор; нет кредитной истории → не ошибка.
- Понятные клиенту сообщения валидации (диапазоны суммы и срока, соответствие цели продукту).

**Кредитное решение** — `services/decision.py`
- В решении сохраняются ежемесячный аннуитетный платёж, факторы скоринга и кто решил (система / специалист).
- Контрпредложение учитывает минимальную сумму продукта.

**Решение андеррайтера** — `POST /applications/{id}/underwriter-decision`
- Одобрить (с возможностью скорректировать сумму, срок, ставку), контрпредложение, запросить уточнения, отказать.
- Для отказа и запроса уточнений обязателен комментарий клиенту.

**API**
- В ответах заявок — название компании и продукта (для очереди банка).
- Создание, изменение и действия по заявке — только от клиента-владельца.

**Тесты** — `tests/test_api.py`, `tests/conftest.py`
- 18 тестов (было 6): все сквозные сценарии через HTTP API, проверки доступа, сбой внешнего сервиса,
  откат при непредвиденной ошибке.

### Frontend (React, TypeScript)

**Клиентская часть**
- Экран входа со списком тестовых учёток (`pages/Login.tsx`).
- Мастер заявки (`pages/NewApplication.tsx`): потребность → подходящий продукт → сумма и срок с
  предварительным расчётом платежа → проверка данных компании (подтягиваются из профиля) и согласие
  на запросы в БКИ / ЕГРЮЛ / ФНС → отправка.
- Страница заявки (`pages/ApplicationPage.tsx`): шкала этапов, подсказка «что дальше» для каждого статуса,
  исправление данных по запросу банка, предложение банка (при контрпредложении — с запрошенной суммой),
  «что повлияло на решение», подписание документов ПЭП (симуляция), график платежей,
  автообновление статуса во время рассмотрения.
- Главная (`pages/Dashboard.tsx`): карточка компании, заявки с подсказкой по каждой.

**Банковская часть**
- Очередь (`pages/BankQueue.tsx`): вкладки «Требуют решения / Ждут клиента / Завершённые / Все»,
  поиск по названию и ИНН, автообновление.
- Карточка заявки (`pages/UnderwriterCard.tsx`): параметры, долговая нагрузка, скоринг с факторами,
  ответы БКИ / ЕГРЮЛ / ФНС, история, форма решения с расчётом платежа.

**Общее**
- Компоненты: `Stepper`, `Timeline`, `Factors`, `nextStep.ts`; расчёты — `utils.ts`.
- Новый дизайн (`styles.css`), адаптивная вёрстка под телефон.
- `package-lock.json` — воспроизводимая сборка через `npm ci`.

### Инфраструктура

- `docker-compose.yml`: healthcheck у backend, frontend стартует после готовности backend, `restart: unless-stopped`.
- `backend/Dockerfile`, `mocks/Dockerfile`: исправлены права на файлы — backend не стартовал
  (`container is unhealthy`), если файлы на диске имели права `600`.
- CI: `npm ci` вместо `npm install`.
- `.env.example`: `DEMO_MODE`, `INTEGRATION_TIMEOUT_S`, `INTEGRATION_RETRIES`.
- `.gitignore`: `*.db`, `*.tsbuildinfo`, временные файлы Vite.
